# 内部と外界の境界

このアプリは `core` と `adapters` の対比を採用します。`core` と `shell` も一般的な呼び方ですが、入力と出力の交換点を明示するため `adapters/inbound` と `adapters/outbound` に分けます。

```text
src/
  core/
    domain/              問題・回答・採点・インポート検証・レポート生成
    application/         ユースケース、入出力ポート
  adapters/
    inbound/react/       ユースケースを呼ぶReact画面
    outbound/browser/    保存・暗号化・ダウンロードなどの実装
  main.tsx               具体実装の組み立て
```

UIはユースケースを起動するinbound adapterです。ストレージやダウンロードはユースケースから利用されるoutbound adapterです。画面に情報が表示されること自体はoutboundへの分類理由にしません。ここではユースケースとの呼び出し関係で分けます。

依存は外側から内側へ向けます。domainはapplicationやブラウザを知りません。applicationはdomainと自身のポートだけを知り、ReactやlocalStorageを参照しません。具体的なadapter同士を画面から組み立てず、`main.tsx` から注入します。

レポート内容を作る純粋関数はdomainに、ファイルとして保存する仕組みはoutboundにあります。同様に日時とID生成もポートを介することで、テストで一定値へ差し替えられます。

## データとシステム

設問はJSONを介して受け取ります。書籍データをコンポーネントに埋め込みません。インポート時に未知の入力を検証し、対応するフィールドだけを採用します。問題の版を記録し、過去の受験結果には受験当時の問題と解説を保持します。

この作業環境では公開システムが `study-room/`、個人データが隣の `software-architecture-the-hard-parts/data/` です。後者を公開システムへコピーしたり、親ディレクトリごとGitに追加したりしません。公開デモと個人用の暗号化カタログも区別します。

## テストの役割

- coreの単体テスト：採点、入力の不正値、学習状態の遷移、出力内容をブラウザなしで確認。
- UIテスト：ポートを差し替え、見える内容、アクセシブルな操作、入力とエラー表示を確認。
- E2E：実ブラウザでパスワード解除、受験、インポート、保存・再開、ダウンロードまでの連携を確認。
- 境界チェック：逆向きのimportやcoreからのブラウザAPI参照を検知。

フロントエンドだけでは認証サーバーによるアクセス制御や生成AIによる自由記述採点は提供しません。単一選択の採点は学習上の目安で、AIへの相談はエクスポートしたMarkdownを使って外部で行います。
